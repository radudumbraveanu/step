## AI-generated marker

Every file written by an AI must start with one short line saying it was generated by AI, including the model that wrote it. Use the comment syntax of the file type.

`<model-id>` below is a placeholder. Replace it with the exact ID of the model you are, the one that actually writes the file. Never copy a model name from this document. Example: if you are Claude Sonnet 5.5, `<model-id>` becomes `claude-sonnet-5-5`; any other model uses its own ID.

- `.md`: a front matter block at the top:
  ```
  ---
  generated-by: AI, model <model-id>
  ---
  ```
- `.html`: `<!-- generated-by: AI, model <model-id> -->`
- `.py`, `.sh`: `# generated-by: AI, model <model-id>`
- `.java`, `.js`, `.ts`, `.css`: `// generated-by: AI, model <model-id>` (use `/* ... */` for CSS)
- `.json` and other formats without comments: skip the marker, or use a `"_generated_by"` key if the format allows it.

Put the marker on line 1, except where the format requires something first (a shebang, `<!DOCTYPE>`, an XML declaration): then put it on line 2.

## Docs

Design docs live in `docs/`, ordered by number (no index file). Read them before changing code. Update them when behaviour changes, so they do not go stale.

- `docs/01-goal.md`: scope and out of scope. Check it before adding a feature. Out of scope: a chat box in the page, multi-user, auth, sandboxing, a build step.
- `docs/02-architecture.md`: files, server endpoints, known limits.
- `docs/03-stack.md`: tech choices and why. Keep it dependency-free (stdlib Python, one HTML file).
- `docs/04-build-plan.md`: what is built and what is untested.
- `docs/05-usage.md`: viewer behaviour for users.
- `docs/06-demo.py`: sample runnable step.
